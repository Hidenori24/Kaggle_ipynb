# 次の一手の計画

Public スコアの返却を待つ間に整理した、次に試す施策の優先順位と手順。

## 0. 現在地と、ローカル→本番の換算率

| 版 | ローカル平均fill_score | 実機Publicスコア |
| --- | --- | --- |
| Or-optチェックポイント | 14.158 | 24.407109 |
| 床置きペナルティ（現行） | 17.123 | **25.042818** |

差分は ローカル **+2.965** に対し 本番 **+0.636**。比率 **0.214**。

最終スコアは fill_score / cog_score / stability_score / placement_score /
soft_item_score の加重平均であり、この比率は**5項目のほぼ等加重平均**
（1/5 = 0.2）と整合する。したがって:

> **ローカルのfill_score +1点 ≈ 本番の総合スコア +0.2点**

この換算率があるので、今後は**提出前にローカルで期待値を見積もれる**。
（cog/stability等を動かす施策には適用できない点に注意。あくまで
fill_score を動かす施策の換算率。）

## 1. 残っている伸びしろ（最優先）

現行版でも、置けている荷物のうちかなりの体積が「境界から5mm以内」で
除外され続けている:

| シナリオ | 現在のfill | 除外ゼロなら | 残りの伸びしろ |
| --- | --- | --- | --- |
| dense_small_container_stress | 12.997 | 20.901 | +7.9 |
| shelf_container_mixed_items | 15.535 | 23.359 | +7.8 |
| single_container_online_large_items | 19.478 | 28.451 | +9.0 |
| two_containers_online_heavy_soft | 14.913 | 22.214 | +7.3 |
| タスク000 | 21.272 | 30.753 | +9.5 |
| タスク001 | 18.545 | 26.335 | +7.8 |
| **平均** | **17.123** | **25.336** | **+8.2** |

換算率0.214を当てると、**全部回収できれば本番 +1.75点（≒26.8点）**。
これが現実的な上限の目安。

### 1.1 【測定済み】残りの除外は 100% が最下層

面ごとの内訳を実測した結果（3シナリオ）:

| シナリオ | 床面違反 | 壁・天井・面取り |
| --- | --- | --- |
| dense_small_container_stress | 11個 0.3161 m³ | **0** |
| single_container_online_large_items | 4個 0.2718 m³ | **0** |
| タスク000 | 4個 0.3799 m³ | **0** |

**壁・天井・面取り面での除外は1件もない。** → 計画のB系（壁・天井マージンの
見直し）は不要と確定。

なお、床面違反のうち一部は「床に接地していない」ように見えるが、詳しく見ると
ソフト貨物（`contactStiffness` が設定された荷物）が**柔らかい接触で床に
めり込み**、底面頂点が床面より下に沈んだものだった（例: `dense_small` の
item 35 は中心が床から80mmなのに最小半径が99mm、落下量も通常の37mmではなく
56mm）。**これらも実質的に最下層の荷物**である。

したがって **残る伸びしろ +8.2点は、全て「最下層の体積」**。
唯一のレバーは**最下層に置く荷物の体積を小さくすること**（＝A系）。

## 2. 施策候補（測定結果を待って優先順位を確定）

### A. 床層の体積をさらに削る（床ペナルティの強化・拡張）

現行 `FLOOR_WASTE_WEIGHT = 1.0`。まだ床層に体積が残っているなら:

- **A-1. 重みのスイープ**（0.5 / 2.0 / 5.0）。単一定数なのでリスクが低く、
  ローカルで直接測れる。最も手軽。
- **A-2. `dh` ではなく「体積 ÷ 支持有効面積」で評価する**。現在は高さのみで
  評価しているが、実際には「その荷物が土台としてどれだけの面積を提供するか」
  も効く。面取り部にはみ出す荷物などは有効面積が小さい。
- **A-3. オフラインプランナーの順序生成にも、壊さない形で反映する**。
  現在は `floor_waste=False` で完全に切っている。順序の生成規則
  （`largest_first_order`）自体を「最初のN個だけ平たい順」にするなど、
  構築のスコアリングを変えずに順序だけ変える方法なら、過去10敗の
  「スコアリング摂動」とは別物になりうる。ただしリスクは高め。

### B. 壁・天井での除外を潰す → **不要と確定（1.1 参照）**

実測の結果、壁・天井・面取り面での除外は1件も無かったため、この系統は
追わない。現行の `SAFETY_MARGIN = 0.012` / `top_margin = 0.02` は
5mm要求に対して十分に効いている。

### C. `LANDING_CLEARANCE = 0.025` の見直し

全ての配置が支持面から25mm浮いた状態で置かれ、そこから落下している
（実測済み）。副作用:

- 段ごとに25mmの高さを浪費 → 積める段数が減る
- 落下の衝撃で既存の積み荷が動く → ドリフト・転倒のリスク

`place_item` は目標位置に**ワープ**してから静定させる方式なので、
めり込みさえ避けられれば小さくできる可能性が高い。
**0.025 → 0.010 / 0.005 のスイープ**。これもローカルで直接測れる。
効果は「段数が増える」形で fill_score に出るはず。

### D. もっと高く積む方向へ寄せる

カウントされるのは床より上の体積だけなので、**上へ積むほど有利**。
現行スコアは `top`（着地高さ）の最小化＝「低く置く」を志向しており、
真の目的と部分的に対立している。ただしここを直接触るのは
構築フェーズの摂動そのもの（過去10敗の領域）なので、**Cで段数を稼ぐ方が
安全**。Cが効かなかった場合の次善策とする。

## 3. 進め方（Public到着後に即実行できる形）

1. 面ごとの内訳測定の結果を見て、**A系 か B系 か**を決める
2. 決めた系統で**最も単純な定数スイープ**から着手（A-1 または B-1/B-2 または C）
   - いずれもローカル6シナリオで直接測定できる
   - 換算率0.214で本番への効果を事前に見積もる
3. ローカルで **+1.0 以上**（＝本番 +0.2以上）の改善が出たものだけ提出する
   - 0.02程度の差は根拠として弱い、というのが今セッションの教訓
4. 提出は1回につき1つの変更だけにする（今回の「全面適用 vs 分離」のように、
   効いた理由を切り分けられる形を保つ）

## 4. やらないこと（このセッションで否定済み）

- cog_score / stability_score / placement_score 狙いのタイブレーク項
  → 実データで一度も発火しない。重みを5000倍にしても無変化（構造的に無力）
- 局所探索フェーズの拡張（SA、ブロック移動など）
  → 既存の2-opt/Or-opt×2000回が近傍を探索し尽くしており、実機で完全に無変化
- 構築フェーズ（`rank_placements`）のスコアリングへの摂動
  → 10戦全敗。今回の床ペナルティも、全面適用した1段階目は同じ形で失敗した
  （オンライン側に限定して初めて効いた）
